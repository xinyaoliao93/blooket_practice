# Blooket 学生入门助手：项目需求文档

版本：1.0 · 日期：2026-10-23

本文是开发和验收的依据。网站第一版本地实现已完成，代码位于 `site`；实际检查记录见 [实现与验证记录](implementation-verification.md)。账号注册、域名购买和正式上线操作尚未执行。

## 1. 已确认的决定

| 项目 | 决定 |
| --- | --- |
| 项目用途 | 新手建站练习，走完一次真实上线流程 |
| 围绕的主题 | Blooket，一款让老师组织学生答题游戏的学习平台 |
| 服务对象 | 不会使用 Blooket 的学生 |
| 网站语言 | 英文；需求文档和部署文档使用中文 |
| 部署平台 | Vercel |
| 域名 | 尚未购买；可以接受购买一个普通域名 |
| 费用方向 | 域名付费，其他部分尽量采用免费方案 |
| 完成条件 | 功能可用 → Vercel 上线 → 绑定域名 → 域名可访问 → 验证 Google Search Console → 提交站点地图 |
| 后续观察 | Google 收录、排名和访问量不作为本次完成条件 |

为了减少第一次建站的复杂度，以下采用默认方案：个人非商业练习、不放广告、不收费、不提供用户注册、不接入 AI 服务。这些是本版范围选择，不代表已验证存在商业需求。

## 2. 一句话说明网站做什么

学生选择“想加入游戏”“加入时遇到问题”或“想自己练习”，网站用简单英文告诉他下一步怎么做，并在需要时带他前往 Blooket 官方页面。

网站暂定名称：**ClassPlay Guide**。名称可以在开发前统一修改；它不是已注册品牌，也不表示同名域名可购买。

首页英文介绍建议：

> Simple Blooket guides for students. Learn how to join a game, find help, or play on your own.

## 3. 为什么选这个范围

| 方案 | 学生能得到什么 | 取舍 |
| --- | --- | --- |
| 只有教程 | 阅读操作步骤 | 最容易制作，但互动练习较少 |
| 教程＋问题选择助手（采用） | 根据自己遇到的问题获得建议 | 功能明确、容易检查，也能练习互动功能 |
| 自己做多人答题游戏平台 | 在本站开房间、实时比赛 | 需要处理多人同步、账号等问题，超出本次练习 |

官方已有帮助中心，本网站的价值应是更简短的学生操作路径，以及按问题组织的建议。没有做搜索量或竞争分析，因此不把“能获得多少访问量”写成承诺。

## 4. 第一版有哪些页面

第一版共有 **6 个正常页面＋1 个找不到页面时的提示页**。所有访客看到的标题、正文、按钮和错误提示均为英文。

| 地址 | 页面 | 必须提供的内容 |
| --- | --- | --- |
| `/` | 首页 | 一句话介绍；三个主要入口；独立帮助网站说明 |
| `/join.html` | 加入游戏指南 | 加入前准备；号码、老师链接、二维码三种加入方式；官方加入入口；遇到问题的入口 |
| `/help.html` | 加入问题助手 | 四种问题选择；对应建议；返回选择；官方帮助链接 |
| `/solo.html` | 独自练习指南 | 与加入课堂游戏的区别；按官方学生指南说明找题和开始个人练习的过程 |
| `/about.html` | 关于网站 | 网站用途；面向学生；与官方的关系；内容依据与更新日期 |
| `/privacy.html` | 隐私说明 | 本站实际收集情况；托管服务可能处理的访问日志；外部链接说明 |
| `/404.html` | 页面不存在 | 英文提示与回到首页按钮；真正返回 404 状态，不伪装成正常页面 |

六个正常页面均提供首页、加入指南、问题助手、个人练习导航，页脚提供 About、Privacy 和独立网站说明。

## 5. 核心功能和使用过程

### 5.1 首页的三个入口

| 按钮英文 | 点击后到哪里 |
| --- | --- |
| Join a game | `/join.html` |
| I can't join a game | `/help.html` |
| Play on my own | `/solo.html` |

学生从首页点击一次即可进入对应内容，不经过注册、弹窗或付费页面。

### 5.2 加入游戏指南

页面说明：加入老师主持的游戏通常需要老师提供的游戏号码、链接或二维码；加入此类游戏不需要学生先创建账号。相关事实以官方说明为依据：[学生是否需要账号](https://help.blooket.com/hc/en-us/articles/17350775717911-Do-students-need-a-Blooket-account-to-play)。

内容按“拿到老师提供的信息 → 在官方页面加入 → 按页面提示操作 → 等待主持人开始”组织，避免把某个游戏的等待规则描述成所有游戏都相同。

提供 **Open official Blooket join page** 按钮，打开 [Blooket 官方加入页面](https://play.blooket.com/)。学生只在官方页面输入游戏号码和昵称。本网站不设置号码或密码输入框。

“没有游戏号码”时，提示向老师或主持人索取。本站不提供号码生成器或声称可用的公开房间号码。

### 5.3 加入问题助手

这是本项目的主要互动功能。它根据学生主动选择的问题，显示固定建议；不连接学生的 Blooket 账号，不检测真实房间状态。

| 可选择的问题（英文） | 必须显示的建议 | 结束入口 |
| --- | --- | --- |
| I don't have a game code | 向老师或主持人索取当前号码、加入链接或二维码 | 加入指南 |
| My game code isn't accepted | 对照老师提供的信息重新检查；确认老师是否仍在主持、是否允许加入；仍失败则询问老师 | 官方加入页面 |
| The page won't load | 刷新；检查普通网页是否能打开；打开官方连接检查工具；学校设备仍失败则请老师协助 | 官方连接检查工具 |
| My homework link won't open | 重新打开老师发来的完整链接；向老师确认作业是否仍可使用；不要用其他课堂游戏号码代替作业链接 | 官方学生指南 |

连接检查工具使用官方提供的 [debug.blooket.com](https://debug.blooket.com/)，依据：[Blooket 连接问题说明](https://help.blooket.com/hc/en-us/articles/17350792576023-How-can-I-debug-Blooket-connection-issues)。

每次只显示当前问题对应的结果。结果区包含“你选的问题”、2～4 条建议、一个相关入口，以及 **Choose another problem** 按钮。

切换问题时旧结果必须被替换。返回选择后可以再次操作。刷新页面回到初始选择状态，不保存个人信息。

无法解决时显示：**Still stuck? Ask your teacher or host for help.** 不显示“已经修复”“号码有效”等未经检测的结论。

不提供绕过学校网络限制的操作说明。浏览器禁用脚本时，页面仍能看到四类问题的基础建议和官方链接。

### 5.4 独自练习指南

明确区分三种情况：加入老师的现场游戏、通过老师链接完成作业、使用自己的账号进行个人练习。个人练习按官方学生指南组织，并提醒账号使用应遵守平台要求；本站不代为注册账号。

说明内容采用原创英文短句，提供 [官方学生指南](https://help.blooket.com/hc/en-us/articles/16015848585879-Blooket-Quick-Start-Guide-for-Students) 入口。开发时再次核对按钮名称，不把官方所有游戏模式逐一复制到本站。

## 6. 明确不做的内容

以下功能不进入第一版，也不作为验收要求：

- 本站注册、登录、保存学生档案、评论和聊天。
- 在本站主持 Blooket 游戏、直接加入房间或获取学生成绩。
- 自动检测房间、生成游戏号码、抓取账号数据。
- 自己制作多人游戏平台、积分、排行榜、角色收集系统。
- AI 自动答疑、AI 出题、题库下载、教师备课工具。
- 广告、会员、支付、推广佣金、邮件订阅和访问统计脚本。
- 多语言切换、大量自动生成的搜索页面、完整的游戏攻略百科。

## 7. 内容与外观要求

- 使用简单英文，一步说明一件事；不能整页照搬官方文章。
- 教程标注实际核对日期，并链接到相应官方资料。
- 遇到官方界面变化时优先更新教程，不凭记忆编写说明。
- 页面采用浅色背景、深色文字、清楚的大按钮；手机上单列显示。
- 首页第一屏直接显示三个主要入口，避免学生先阅读长篇介绍。
- 不使用看起来像官方登录页的外观；不复制官方标志或角色图作为本站标识。
- 页脚统一显示：**Independent student guide. Not affiliated with or endorsed by Blooket.**
- About 页说明 Blooket 名称归其相应权利人所有，本站提供独立使用指引。
- 手机宽度约 360 像素时无横向滚动；文字不被按钮或卡片遮挡。
- 按 Tab 能依次选中链接和按钮；当前选中位置清楚可见。
- 问题选择使用真实按钮；结果变化应能被使用辅助阅读工具的人感知。
- 内容图片不是第一版必需项，使用文字即可，不等待图片制作。

## 8. 技术方案：由开发者负责

采用 **HTML＋CSS＋原生 JavaScript＋GitHub＋Vercel**。

你可以把它理解成：HTML 放内容、CSS 管外观、JavaScript 实现选择问题的互动；GitHub 保存文件，Vercel 让其他人通过网址访问。

该网站没有需要长期保存的用户数据，第一版不需要数据库、服务器程序、Node.js、依赖安装或付费接口。教程正文直接写在页面文件中，让访客和搜索引擎都能读取。

开发交付结构必须如下；文档与网站文件分开，Vercel 只发布 `site` 文件夹：

```text
项目文件夹/
├─ docs/
│  ├─ blooket-project-requirements.md
│  └─ blooket-deployment-guide.md
└─ site/
   ├─ index.html
   ├─ join.html
   ├─ help.html
   ├─ solo.html
   ├─ about.html
   ├─ privacy.html
   ├─ 404.html
   ├─ robots.txt
   ├─ sitemap.xml
   ├─ favicon.svg
   └─ assets/
      ├─ styles.css
      └─ help.js
```

正常页面地址保持 `.html` 结尾；首页用 `/`。不增加复杂的网址改写规则，也不把所有不存在的地址都改成首页。

页面之间使用相对文件链接，方便本地打开检查。正式的页面主地址和站点地图使用最终购买的完整域名。

## 9. Google 提交所需内容

以下是开发时就要准备的文件和页面信息，不是上线后再临时补齐的功能。

| 项目 | 要求 |
| --- | --- |
| 页面语言 | 正常页面声明为英文，例如 HTML 的 `lang="en"` |
| 页面标题 | 六个正常页面各不相同，准确描述页面内容 |
| 页面简介 | 每个正常页面用简短英文说明能提供什么帮助 |
| 正文标题 | 每个正常页面一个清楚的主要标题 |
| canonical | 告诉搜索引擎该页的正式主地址；六个正常页面分别使用最终 HTTPS 域名下对应的地址 |
| `/robots.txt` | 允许抓取正常页面，并写入正式的站点地图地址 |
| `/sitemap.xml` | 只包含六个正常页面的完整 HTTPS 地址 |
| 不纳入站点地图 | 404、外部 Blooket 页面、Vercel 预览地址、查询参数组合、文档文件 |
| 抓取条件 | 正式网站无需登录、没有阻止抓取的 `noindex` 或全站禁止规则 |
| 更新日期 | 如果站点地图填写修改日期，必须是真实修改时间；也可以省略该字段 |

不能保证因为完成这些内容就会被 Google 收录或取得排名。[Google 官方站点地图说明](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap?hl=zh-CN)

## 10. 隐私与费用范围

隐私页应按实际实现编写：本站不主动索取姓名、邮件、账号密码或游戏号码；问题选择不上传、不长期保存；未接入广告、分析脚本或用户追踪。

同时说明托管服务可能按其自身政策处理 IP 地址等技术访问日志，并提供 [Vercel 隐私政策](https://vercel.com/legal/privacy-policy) 链接。不要写“任何人都完全不收集任何信息”。点击外部网站后适用对方政策。

| 项目 | 第一版费用安排 |
| --- | --- |
| 域名 | 用户自行购买，检查首年价和续费价；按年续费 |
| GitHub | 使用个人免费账号保存项目 |
| Vercel | 个人非商业练习优先使用 Hobby，在当期规则和用量范围内使用 |
| Google Search Console | 免费验证和提交 |
| 额外服务 | 不购买数据库、邮箱、AI 接口、付费模板等 |

Vercel Hobby 面向个人非商业用途。如果以后改为商业运营，需要重新评估计划和费用。[Vercel Hobby 官方说明](https://vercel.com/docs/plans/hobby)

开发交付时逐项检查；任何一项失败，先修复再继续部署。

| 编号 | 操作 | 通过标准 |

| F01 | 点击首页三个主要按钮 | 分别进入正确页面 |
| F02 | 打开加入指南 | 三种加入方式说明完整，官方加入按钮可用 |
| F03 | 依次选择助手的四个问题 | 每次显示相应建议，不混入上一个问题的内容 |

## 12. 项目完成条件与交付物

### 12.1 六个完成条件

1. 上面的功能验收通过。
2. Vercel 的正式部署成功，自动生成的网址可访问。
3. 购买并绑定自己的域名。
4. 通过该域名直接访问网站，HTTPS 正常；手机和未登录浏览器均可访问。
5. Google Search Console 显示域名所有权验证成功。
6. 正式域名下的站点地图可读取，并已在 Search Console 提交；“无法获取”等明确错误要修复，不把失败提交当完成。

“处理成功”是理想核对状态。如果 Google 仍在处理中，记录已经提交的证据，不把等待收录或排名加入本项目范围。

### 12.2 最终交付物

- 完整 `site` 文件夹与两份中文文档。
- 用户自己账号下的 GitHub 项目。
- Vercel 项目及正式部署地址。
- 购买并绑定的域名，以及域名续费提醒记录。
- Search Console 验证成功记录。
- 站点地图提交记录及当时状态。

记录凭据时只保存网址、状态和日期，不保存密码或恢复码。

## 13. 交给 AI 或开发者的开发指令

在你准备开始做网站时，把下面这段话与本文件一起交给开发者或 AI。它用于后续开发，不表示本次已经执行开发。

> 请按照《Blooket 学生入门助手：项目需求文档》开发第一版。采用原生 HTML、CSS、JavaScript，将可直接发布的网站文件全部放在 site 文件夹，文档保留在 docs。实现六个正常页面、一个真正的 404 页面和四个分支的问题助手；所有访客内容用简单英文。教程正文直接写在 HTML 中，助手提供脚本不可用时的基础建议。不要新增账号、数据库、AI 接口、广告或统计脚本，不要代替 Blooket 执行游戏操作。为最终域名准备 canonical、robots.txt 和包含六页的 sitemap.xml；域名尚未购买时可以统一使用 example.com 作为明确的临时示例，但要列出正式发布前所有替换位置。再次核对官方资料，写原创说明，并执行文档中的功能验收。交付本地预览方法、完整文件和检查结果，不代为购买域名或发布。
